Glossary

Plain-language definitions of every term used in these docs. Security has a lot of jargon; none of it is required reading, but this is here when you need it.

Security terms

TermMeaning
SASTStatic Application Security Testing. Reading your source code (without running it) for dangerous patterns.
DASTDynamic Application Security Testing. Probing a running application from the outside, as an attacker would.
SCASoftware Composition Analysis. Finding known vulnerabilities and license issues in the third-party libraries you use.
SBOMSoftware Bill of Materials. A machine-readable list of every component in your software, like an ingredients label.
VEXVulnerability Exploitability eXchange. A statement saying, for each known vulnerability, whether it actually affects your product (for example "false positive" or "fixed").
CVECommon Vulnerabilities and Exposures. A public id (CVE-2021-23337) for one specific vulnerability.
GHSAGitHub Security Advisory id. Many CVEs also have one; Night Owl prefers the CVE when both exist.
CWECommon Weakness Enumeration. A category of mistake (CWE-89 is SQL injection) rather than one specific bug.
OSVOpen Source Vulnerabilities, a free database of advisories across many ecosystems. OSV.dev is where Night Owl looks things up.
SARIFStatic Analysis Results Interchange Format. A standard JSON layout for scanner results that many tools can read.
Taint analysisTracking data from where it enters (a source) to where it could do harm (a sink), noting if anything cleans it (a sanitizer) on the way.
InjectionUntrusted input being treated as code: SQL injection, command injection, and so on.
XSSCross-site scripting. Untrusted input ending up as active HTML or script in a web page.
Path traversalUsing ../ in a file name to read or write files outside the intended folder.
TLS validationChecking that the server you connect to really is who it claims. Disabling it allows man-in-the-middle attacks.
ReachabilityWhether your code actually uses a vulnerable package or function. A vulnerability you can't reach is lower priority.
Transitive dependencyA library pulled in by one of your libraries, not by you directly.
LockfileA file (package-lock.json, uv.lock, …) that records the exact versions installed. Night Owl scans lockfiles because they show what you really run.
Cyclomatic complexityA count of the independent paths through a function. High numbers mean code that is hard to test and easy to get wrong.

Night Owl terms

TermMeaning
EngineAn open-source scanner Night Owl runs (Syft, OSV-Scanner, gitleaks, Opengrep, cppcheck, Trivy, lizard, ZAP, nuclei).
AdapterThe Night Owl code that runs one engine and translates its output into findings.
FindingOne reported problem, in Night Owl's common format. See Findings and reports.
FingerprintA finding's stable id. The same problem keeps the same fingerprint across scans and engines.
Gate / quality gateThe rule that turns findings into pass or fail (exit code 0 or 1).
TriageRecording a decision about a finding: false positive, accepted risk, confirmed, fixed.
ContextWhere a finding lives: production, test, example, docs, generated or vendored. Only production gates by default.
PolicyThe committed .nightowl/policy.yml that holds a team's rules.
ManifestThe signed list of exact engine versions and image digests Night Owl may run.
Sequence numberA counter in the manifest that only increases, so an attacker can't make you go back to an older, vulnerable engine.
DigestThe cryptographic hash of a container image. Pinning by digest means a tag can't be quietly re-pointed to different contents.
CanaryA built-in set of known-vulnerable samples. After an update, every engine must still find them; otherwise the update is rolled back.
Maturity windowThe waiting period (14 days for engines, 2 for base images) before the watch bot proposes a new upstream release.
Watch botThe scheduled workflow that opens a pull request when engines or base images have newer releases.
Scope fileThe JSON file that says what an active pen test may touch, who approved it, and until when.
Scope proxyNight Owl's own HTTP proxy that every pen-test request must pass through, so limits are enforced in code.
BaselineAn earlier report to compare against, so only new findings count.
